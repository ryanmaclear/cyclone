# AGENTS.md

Guidance for coding agents working in this repository.

## Project Overview

Cyclone is TypeScript control software for generating and running filament-winding toolpaths for Marlin-driven machines. The codebase includes a CLI, Electron entry points, a planner, a plotter, and serial communication with Marlin firmware.

Be careful with behavioral changes: generated G-code and streamed commands can move real hardware.

## Repository Layout

- `src/cli-entry.ts`: CLI command entry point.
- `src/main.ts`, `src/preload.ts`, `src/renderer.ts`: Electron application entry points.
- `src/marlin-port.ts`: Marlin serial communication.
- `src/planner/`: toolpath planning, machine model, and planning types.
- `src/plotter/`: plotting helpers and types.
- `src/helpers.ts`: shared helpers.
- `index.html`: Electron renderer HTML.
- `dist/`: TypeScript build output, generated by `npm run build`.

## Common Commands

- Install dependencies: `npm i`
- Build: `npm run build`
- Watch TypeScript: `npm run watch`
- Run Electron app: `npm run start`
- Run CLI: `npm run cli -- <command>`
- Lint, if configured locally: `npm run lint`

Run `npm run build` after TypeScript changes. If changing CLI behavior, also run the relevant `npm run cli -- ...` command with a small input where practical.

## Coding Conventions

- Follow the existing TypeScript style and module boundaries.
- Keep planner logic in `src/planner/` and plotting logic in `src/plotter/`.
- Prefer explicit types for public interfaces and shared data structures.
- Keep comments short and focused on non-obvious machine, geometry, or protocol behavior.
- Avoid broad refactors unless they are needed for the requested change.
- Do not commit generated `dist/` changes unless the user explicitly asks for build artifacts.

## Safety Notes

- Treat G-code generation and Marlin streaming as safety-sensitive.
- Preserve units carefully: carriage coordinates are millimeters, while mandrel and delivery-head axes use degrees.
- Be cautious around feed rates, axis mapping, lock/lead-in/lead-out behavior, and terminal layers.
- Do not silently change output semantics; document any intentional change to generated motion.

## Git Hygiene

- Check `git status --short` before editing.
- Do not revert unrelated user changes.
- Keep patches scoped to the requested task.
- If the working tree contains unrelated changes, leave them alone.

## graphify

This project has a knowledge graph at graphify-out/ with god nodes, community structure, and cross-file relationships.

When the user types `/graphify`, use the installed graphify skill or instructions before doing anything else.

Rules:
- For codebase questions, first run `graphify query "<question>"` when graphify-out/graph.json exists. Use `graphify path "<A>" "<B>"` for relationships and `graphify explain "<concept>"` for focused concepts. These return a scoped subgraph, usually much smaller than GRAPH_REPORT.md or raw grep output.
- Dirty graphify-out/ files are expected after hooks or incremental updates; dirty graph files are not a reason to skip graphify. Only skip graphify if the task is about stale or incorrect graph output, or the user explicitly says not to use it.
- If graphify-out/wiki/index.md exists, use it for broad navigation instead of raw source browsing.
- Read graphify-out/GRAPH_REPORT.md only for broad architecture review or when query/path/explain do not surface enough context.
- After modifying code, run `graphify update .` to keep the graph current (AST-only, no API cost).
